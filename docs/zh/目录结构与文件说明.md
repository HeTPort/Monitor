# 工具目录结构与文件作用

## 1. 使用者看到的发布目录

```text
MonitorRelease/
  vmin_judge.exe       Monitor 主机入口，CPU/GPU/NPU 共用
  config/             建议附带的可编辑配置副本
  tools/              可选外置资产/工具；内置资源也可由程序携带
  docs/               中文使用、用例原理和日志交接说明
MonitorResults/       显式指定的结果输出目录
MonitorState/         显式指定的配对、基线与部署状态目录
```

可执行文件内携带的资源与外置 config/tools 是不同来源；不要把内部临时解包目录当成可编辑文件夹。程序默认寻找可执行文件相邻资源及内置资源；输入路径还受配置文件所在位置、外置 config 和当前工作目录影响，现场应显式指定 config/output/state。具体路径规则见[使用指南](使用指南.md)。

## 2. Monitor 源码和配置

| [deployment.py](../../src/deployment.py) | 资产清单、哈希部署与部署核验 |
| [serial_port_manager.py](../../src/serial_port_manager.py)、[serial_monitor.py](../../src/serial_monitor.py) | 配对、串口读取与诊断 |
| [uart_protocol.py](../../src/uart_protocol.py)、[events.py](../../src/events.py) | 帧编码/CRC、身份、序号和事件结构 |

| [policy_engine.py](../../src/policy_engine.py)、[verification_contract.py](../../src/verification_contract.py) | 公共 verdict、显式错误、校验覆盖与计数矛盾检查 |
| [artifact_store.py](../../src/artifact_store.py)、[evidence_collection.py](../../src/evidence_collection.py) | 原子写结果、原始证据回收、文件集合与哈希 |
| [qualification.py](../../src/qualification.py)、[npu_qualification.py](../../src/npu_qualification.py) | 合格持续样本、参考与执行位置要求 |
| [qualification_artifacts.py](../../src/qualification_artifacts.py)、[baselines.py](../../src/baselines.py) | golden、审批基线和相关产物管理 |
| [result_formatter.py](../../src/result_formatter.py) | 结果格式化；公共 report 从已有证据生成报告 |
| [stress.py](../../src/stress.py) | 可执行文件内的顺序压测编排，调用同一个主程序公共命令 |
| [scheduler_components.py](../../src/scheduler_components.py) | 调度相关描述；不表示会执行调压/锁频/绑核 |

src 中部分旧名称兼容模块用于原接口导入，不能把文件名相近理解为存在多套新的执行流程。维护时优先沿公共入口、run_orchestrator 和 policy_engine 查调用关系。

## 4. workload 目录

```text
npu-workload/
  build.ps1 / build.sh    Windows/Linux 集中构建入口
  scripts/build.py       解析组件、目标平台和编译选项
  cpuworkload/           CPU 工程
  gpuworkload/           GPU 工程
  npuworkload/           NPU 工程
  tests/                 跨组件校验与构建检查
  docs/zh/               中文编译和设计说明
  build/unified/         每次构建独立产物与日志（运行构建后产生）
```

| 文件或目录 | 大致作用 |
|---|---|
| [集中入口](../../../npu-workload/scripts/build.py) | 按需选择 cpu/gpu/npu/relay/monitor；区分 host 与设备目标 |
| 三工程 `CMakeLists.txt` 与原 build 脚本 | 各子工程编译配置，集中入口复用对应构建逻辑 |
| 三工程 `include/` | 配置、后端、张量/指标/事件等接口声明 |
| 三工程 `src/main.cpp`、`config.cpp`、`profile.cpp` | 参数入口、合法性检查与内置预设 |
| 三工程 `src/runner.cpp` | 初始化、预热、工作单元循环、校验与停止 |
| 三工程 `src/backend_factory.cpp`、`src/backends/` | 实际实现选择和硬件/框架后端 |
| 三工程 `src/verifier.cpp`、`metrics.cpp`、`logger.cpp` | 正确性、吞吐/延迟统计和 JSONL 输出 |
| [CPU backends](../../../npu-workload/cpuworkload/src/backends/) | integer、floating_point、matrix、memory、mixed 和 null |
| [GPU shaders](../../../npu-workload/gpuworkload/shaders/) | 算术、超越函数、纹理、填充/混合着色程序 |
| [GPU backends](../../../npu-workload/gpuworkload/src/backends/) | GLES、Vulkan 图形/compute、OpenCL 与 null |
| [NPU profiles](../../../npu-workload/npuworkload/profiles/) | 模型 manifest、模型文件与固定输入；保持相对布局 |
| [NPU manifest.cpp](../../../npu-workload/npuworkload/src/manifest.cpp)、[tensor.cpp](../../../npu-workload/npuworkload/src/tensor.cpp) | 资产哈希、形状、dtype、layout、量化与字节检查 |
| [NPU tflite_delegate](../../../npu-workload/npuworkload/src/backends/tflite_delegate/) | 动态库、模型/解释器、delegate、输入输出与调用 |
| [NPU tests](../../../npu-workload/npuworkload/tests/) | null/fake 生命周期与失败路径；不证明真实 NPU 执行 |
| [third_party](../../../npu-workload/npuworkload/third_party/) | 模型来源、许可和归属说明，随资产保留 |

算法函数和各模型张量的详细解释见[用例原理详解](用例原理详解.md)。生成的日志与构建目录不得当作输入源码编辑；测试失败也要保留相应目录。

## 5. 测试输出与交接

PC result、run-manifest 和 full 串口记录属于主机证据；设备 workload/events/summary/FINAL 和 telemetry 属于板端证据；collect 将它们复制到 PC 并核验。压测执行器再在 campaign 下追加 ledger 与每步操作日志。具体文件意义和定位顺序见[压测与日志交接](压测与日志交接.md)。
