## 本轮检查

本轮保持原有操作流程，将可选压测编排接入可执行文件，复用同一部署、运行、判定与收集实现。实际结果如下：

| 检查 | 结果 |
|---|---|
| Windows 回归 | 190 项，跳过 12 项 POSIX 环境检查，其余通过 |
| Linux 回归 | 190 项全部通过 |
| 原打包定义 | 使用原 vmin_judge.spec 成功生成检查用 exe |
| exe 独立运行 | 清除 Python 环境路径，在源码目录之外启动成功 |
| 三模块入口 | exe 可分别列出 CPU/GPU/NPU profile；三模块压测 dry-run 均生成相同公共准备/运行/收集命令 |
| exe 子进程 | 实际调用同一个 exe 的公共命令成功，不需要 main.py |
| 通用阶段计划 | 支持可配置阶段、无固定日程；旧独立入口兼容检查通过 |
| 原文保留 | 20 份原有文档逐文件核对未变；中文入口说明同步更新 |
| 中文链接 | 292 个本地文档/源码路径检查通过 |
| 表格 | 六个工作表逐表预览，公式临时输入检查后恢复空白；无错误公式 |

以上 exe 是主机入口与打包兼容检查产物，未携带完整真实板端 tools，未作为实机发布包交付。原 scripts/build.ps1 继续要求真实设备产物，缺少时明确拒绝打包；默认 CPU/GPU 和可选 IncludeNpu 的资源要求保持。原 vmin_judge.spec 已能收集新入口和配置，无需更换打包方式。

新增入口的阶段执行仍调用原 validate/deploy/verify-deployment/run/collect/report；平台 probe、板卡匹配和后端能力按原要求核对。没有连接设备，不把 dry-run 写成实机通过。
