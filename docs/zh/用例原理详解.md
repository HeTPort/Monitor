# 用例原理详解与源码索引

本文依据随包源码说明实际执行行为。链接为相对文件路径，解压后保留 npu-monitor 与 npu-workload 相邻结构即可离线跳转。用例参数全表见[用例总表](用例总表.md)。

## 1. 三类工作单元和校验

CPU 以 batch 为工作单元，GPU 以 frame/dispatch 为工作单元，NPU 以 inference 为工作单元。初始化、预热、正式测量、校验、summary 和清理分开。工作单元真实完成后才增加计数；verify_interval 选择校验点，success_log_interval 只控制成功日志抽样，失败立即输出。

源码：[CPU runner](../../../npu-workload/cpuworkload/src/runner.cpp)、[GPU runner](../../../npu-workload/gpuworkload/src/runner.cpp)、[NPU runner](../../../npu-workload/npuworkload/src/runner.cpp)、[校验调度](../../../npu-workload/npuworkload/include/avs/verify_schedule.h)。

checksum 相同只说明所比较的结果相同。CPU 初始化时可计算本次期望值，NPU 缺少外部 golden 时可用首次输出作重复一致性参考；正式独立正确性需要可信条件建立的参考。GPU 图像逐字节校验要求相同 shader、参数和产物。哈希不能证明硬件执行位置。

## 2. CPU 各计算核

### 整数运算链

执行原理：IntegerKernel 以 seed 初始化三个 uint64 状态；每次迭代做乘加、异或、循环移位与右移，最后用 Mix64 合并。后一轮依赖前一轮状态，因此它主要形成确定性的整数运算链。threads 指定独立 worker，每个 worker 使用不同派生种子。

参数与压测：iterations 增加每 batch 工作；threads 增加并行 worker。working_set_kb 不控制这个核的数组，因为此实现不使用工作集数组。

记录与边界：看 batch_count、operations_per_sec_avg、batch_time_ms_p99 和首次 checksum 失败。operation_count 是软件估算操作数，不是硬件退休指令计数；不保证覆盖所有整数指令或 SIMD。

源码：[integer_backend.cpp](../../../npu-workload/cpuworkload/src/backends/integer/integer_backend.cpp)；并行工作与结果归并见 [RunWorkers](../../../npu-workload/cpuworkload/src/backends/kernel_common.h)。

### 双精度浮点递推

执行原理：FloatingPointKernel 用三个 double 状态反复做乘加与差分，越界时缩放或平移以保持数值范围。结尾 memcpy 取浮点位模式，经 Mix64 生成 checksum。其结果依赖运算次序与编译器浮点选项。

参数与压测：iterations 增加递推长度，threads 增加并行 worker。改优化等级或浮点选项后需重新核对可信参考。

记录与边界：看持续吞吐、batch 尾延迟与校验；源码没有显式向量 intrinsic，不可由名称宣称覆盖 NEON/FMA 的全部路径。

源码：[floating_point_backend.cpp](../../../npu-workload/cpuworkload/src/backends/floating_point/floating_point_backend.cpp)；并行工作与结果归并见 [RunWorkers](../../../npu-workload/cpuworkload/src/backends/kernel_common.h)。

### 小型稠密矩阵乘法

执行原理：MatrixKernel 为 A/B/C 分配 double 数组，用确定性种子填充 A/B。以 row/column/k 三重循环执行 C 的乘加；重复之间保留很小的旧 C 分量。最终对全部 C 的位模式归并 checksum。维度由 working_set_kb 推算，并限制在 8 至 64；重复次数约为 iterations/(n*n)，至少一次。

参数与压测：working_set_kb 在维度上限内影响 n，超过上限不会继续扩大矩阵。iterations 控制重复次数，threads 并行执行独立矩阵。每次 batch 都包含该核中的分配、填充和归并。

记录与边界：看矩阵吞吐和 batch 延迟；这是普通软件循环，不调用 BLAS 或专用矩阵指令，不等同 NPU 矩阵单元测试。

源码：[matrix_backend.cpp](../../../npu-workload/cpuworkload/src/backends/matrix/matrix_backend.cpp)；并行工作与结果归并见 [RunWorkers](../../../npu-workload/cpuworkload/src/backends/kernel_common.h)。

### 状态驱动随机读改写

执行原理：MemoryKernel 按 working_set_kb 为每个 worker 分配 uint64 数组，至少 128 元素。每轮从状态和 accumulator 生成索引，读取该位置、更新校验累加值并写回新值。结束时从最多 64 个分散位置继续归并。访问地址依赖先前结果。

参数与压测：working_set_kb 改变每 worker 数组大小；threads 会增加总工作集。iterations 控制随机访问次数。要判断落在哪级缓存，需要结合实际缓存容量与测量。

记录与边界：看吞吐/延迟及 checksum；该实现不是顺序带宽基准，也不是遍历每个 bit 的完整内存故障算法。

源码：[memory_backend.cpp](../../../npu-workload/cpuworkload/src/backends/memory/memory_backend.cpp)；并行工作与结果归并见 [RunWorkers](../../../npu-workload/cpuworkload/src/backends/kernel_common.h)。

### 整数、浮点与随机访存混合

执行原理：MixedKernel 在同一循环交织 uint64 线性递推、位移/异或、状态索引的数组读写与两个 double 的乘加。结束时取最多 32 个数组样本和浮点位模式形成 checksum。它直接实现混合核，没有依次调用整数、浮点、矩阵、内存四个后端。

参数与压测：threads/iterations/working_set_kb 分别影响并行数、循环长度和每 worker 数组；改变任何一项都会改变工作/参考身份。

记录与边界：看温度、实际频率与吞吐变化；mixed 不包含 MatrixKernel，不能代替独立 matrix 用例。

源码：[mixed_backend.cpp](../../../npu-workload/cpuworkload/src/backends/mixed/mixed_backend.cpp)；并行工作与结果归并见 [RunWorkers](../../../npu-workload/cpuworkload/src/backends/kernel_common.h)。

### 空闲与框架对照

执行原理：NullBackend 不执行真实 CPU 算法，runner 按 profile 的占空比与进展规则运行。idle 配置用于连接、生命周期与日志对照。

参数与压测：duty_cycle=0 形成空闲对照；需要真实压力时选择 integer/mixed 等后端。

记录与边界：框架通过不计为有效计算负载；软件等待不能证明 CPU 已进入某个硬件低功耗状态。

源码：[null_backend.cpp](../../../npu-workload/cpuworkload/src/backends/null/null_backend.cpp)；并行工作与结果归并见 [RunWorkers](../../../npu-workload/cpuworkload/src/backends/kernel_common.h)。

### 突发、持续升温与高强度

burst/thermal/stress_extreme 是负载组织与参数预设，不是新的计算核。当前 CPU 对应配置使用 mixed：burst 让活跃与休眠交替，thermal 延长测量时段，extreme 增加迭代与工作集。休眠与负载结束处会产生间隔，不能把多个短运行的墙钟总跨度当作连续满负载时长。

源码：[内置预设](../../../npu-workload/cpuworkload/src/profile.cpp)、[占空比与停止条件](../../../npu-workload/cpuworkload/src/runner.cpp)。Monitor 参数见 [cpu_burst_qualification_kirin9030.json](../../config/workloads/cpu_burst_qualification_kirin9030.json)、[cpu_thermal_qualification_kirin9030.json](../../config/workloads/cpu_thermal_qualification_kirin9030.json)、[cpu_stress_extreme_qualification_kirin9030.json](../../config/workloads/cpu_stress_extreme_qualification_kirin9030.json)。

## 3. GPU 各图形路径

Monitor 当前 Vulkan profile 使用 mode=offscreen。后端创建离屏 RGBA8 目标，提交全屏图形绘制，等待 GPU，读回输出供校验。它不通过屏幕呈现来衡量 FPS；主机提交/等待/读回开销和有效 GPU 时间分别看待。后端选择逻辑见 [backend_factory.cpp](../../../npu-workload/gpuworkload/src/backend_factory.cpp)，图形资源和提交见 [vulkan_graphics_backend.cpp](../../../npu-workload/gpuworkload/src/backends/vulkan/vulkan_graphics_backend.cpp)。

### ALU

执行原理：每个片段从 uv 和常数初始化 vec4，在 iterations 循环内执行分量乘加、fract 和分量重排。前后迭代相互依赖，形成持续向量算术。

压测与边界：增加像素数与 iterations 增加算术量；具体指令仍由着色编译器决定，不能直接对应硬件端口覆盖。

源码：[workload_alu](../../../npu-workload/gpuworkload/shaders/vulkan/workload.frag)（搜索函数名 `workload_alu`）；全屏顶点输入见 [fullscreen.vert](../../../npu-workload/gpuworkload/shaders/vulkan/fullscreen.vert)。

### SFU

执行原理：以 uv 生成两个状态，在循环中交替 sin/cos 并使用更新后的状态，输出其绝对值与 fract 组合。

压测与边界：用于观察超越函数密集路径；sin/cos 的硬件实现由驱动决定，不代表已隔离某个专用 SFU。

源码：[workload_sfu](../../../npu-workload/gpuworkload/shaders/vulkan/workload.frag)（搜索函数名 `workload_sfu`）；全屏顶点输入见 [fullscreen.vert](../../../npu-workload/gpuworkload/shaders/vulkan/fullscreen.vert)。

### 纹理

执行原理：每个片段在 iterations 外循环内计算偏移，内循环按 texture_count 对同一个 sampler2D 做多次 texture 采样并累加，更新 uv，最后归一化输出。

压测与边界：texture_count 是同一纹理重复采样倍率，不是纹理对象数。纹理尺寸、缓存、过滤与坐标影响瓶颈；不自动等同纯显存带宽测试。

源码：[workload_texture](../../../npu-workload/gpuworkload/shaders/vulkan/workload.frag)（搜索函数名 `workload_texture`）；全屏顶点输入见 [fullscreen.vert](../../../npu-workload/gpuworkload/shaders/vulkan/fullscreen.vert)。

### 填充

执行原理：直接把 uv 组合成 RGBA 输出写入离屏渲染目标，片段运算很少，主要用分辨率增加片段与写入规模。

压测与边界：这个函数没有 iterations 循环，调大 iterations 不增强此路径。总开销仍有提交、等待、图像转换与读回。

源码：[workload_fill](../../../npu-workload/gpuworkload/shaders/vulkan/workload.frag)（搜索函数名 `workload_fill`）；全屏顶点输入见 [fullscreen.vert](../../../npu-workload/gpuworkload/shaders/vulkan/fullscreen.vert)。

### 混合与 light/mid/heavy

执行原理：在同一片段循环交织向量算术、sin/cos 偏移、纹理重复采样、fract 和通道混合。light/mid/heavy 是分辨率、循环次数和采样倍率的预设。

压测与边界：不是实际游戏帧；同名 profile 在原生默认与 Monitor JSON 中参数可能不同，使用实际 JSON。thermal/extreme 同样复用此 shader 增强时长或规模。

源码：[workload_mixed](../../../npu-workload/gpuworkload/shaders/vulkan/workload.frag)（搜索函数名 `workload_mixed`）；全屏顶点输入见 [fullscreen.vert](../../../npu-workload/gpuworkload/shaders/vulkan/fullscreen.vert)。

### compute、OpenCL、GLES 与 null 的区别

Vulkan compute 和 OpenCL 的 texture_like 通过计算模拟数据行为，不等于上述 texture() 图形采样。GLES 使用自身图形实现。虽然原生工程有多个后端，Monitor 是否允许配置还受校验和设备能力约束；不能把源码里存在后端等同已经完成其板端接入。null 用于主机框架自检，不提交真实 GPU 工作。

源码：[Vulkan compute](../../../npu-workload/gpuworkload/src/backends/vulkan/vulkan_backend.cpp)、[OpenCL](../../../npu-workload/gpuworkload/src/backends/opencl/opencl_backend.cpp)、[GLES](../../../npu-workload/gpuworkload/src/backends/gles/gles_backend.cpp)、[null](../../../npu-workload/gpuworkload/src/backends/null/null_backend.cpp)。

## 4. NPU 模型与推理路径

真实后端动态加载 TFLite C runtime，创建模型与 interpreter，挂接厂商 delegate，分配张量并检查类型、维度和字节大小，写入固定输入，提交调用、等待并读回输出。runner 当前逐次提交后等待，再进入下一次推理；不是多请求并行流水线。

INT8 输入/输出是量化张量，量化比例与零点由 manifest 定义。checksum 比较输出字节，不通过分类正确率或应用级准确率判断。固定样本反复推理有利于复现与输出一致性检查，但不能代表多输入、多形状、全部算子或所有工作集规模。

源码：[runtime/delegate 与张量拷贝](../../../npu-workload/npuworkload/src/backends/tflite_delegate/tflite_delegate_backend.cpp)、[资产与张量核验](../../../npu-workload/npuworkload/src/manifest.cpp)、[输出校验](../../../npu-workload/npuworkload/src/verifier.cpp)、[注册张量契约](../../../npu-workload/npuworkload/src/profile.cpp)。

### KWS01：关键词识别

张量：INT8 输入 [1,49,10,1]，490 字节；INT8 输出 [1,12]，12 字节。

原理与覆盖：输入是已准备的 MFCC 特征窗口，模型输出分类分数。每次重复使用同一窗口；不包含实时采音、特征计算、关键词数据集准确率统计。

配置与资产：[manifest（张量/量化/资产哈希）](../../../npu-workload/npuworkload/profiles/kws01/manifest.json)、[模型与输入目录](../../../npu-workload/npuworkload/profiles/kws01/assets/)；Monitor 示例 [npu_kws01_load.json](../../config/workloads/npu_kws01_load.json)。

### IC01：图像分类

原理与覆盖：输入是模型边界上的小型 RGB 图像张量，输出类别分数。推理不包含摄像头、图像解码、缩放或完整视觉应用链路。

### AD01：异常检测

### smoke、load 与 qualification

三个用途复用相同模型配置与公共 Monitor 流程：smoke 为 null 资产/生命周期检查；load 为真实 delegate 重复调用，缺少外部参考时仅能做运行内一致性；qualification 额外要求可信 golden、逐次校验和绑定的厂商执行证据。

`fallback_used=false` 只能表明 runner 没有主动回退。厂商 delegate 可能接管部分算子，因此必须从厂商诊断确认执行位置，不能靠调用成功推断 full_npu。完整要求见 [NPU 适配与资产/位置检查](../../src/target_adapters.py)、[NPU 资格化证据检查](../../src/npu_qualification.py)。

## 5. 如何按原理选择压测

先用 smoke 建立链路，再分别运行定向核/图形路径/模型，最后增加时长和强度。只改变一个工作量维度便于解释瓶颈；每次保留实际配置、资产哈希、板卡条件和首错。各定向用例的通过不能推导芯片全部单元覆盖，热持续用例也需实际温度趋势确认是否稳定。
